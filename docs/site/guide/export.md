# 导出与应用代码

Miweb 生成调整结果，由你审查后应用到自己的项目。它不会自动保存到原项目，也不会部署目标网站。

## 选择输出

| 导入方式 | 推荐输出 | 应用方式 |
| --- | --- | --- |
| 受支持的本地项目 / 示例 | 修改后的源码或最小 diff | 检查后替换对应文件，或应用 diff |
| 公网、本地或局域网 URL | CSS 补丁 | 放在原页面样式末尾 |
| 样式优先级不能可靠覆盖的节点 | JavaScript 补丁 | 按交付窗口说明放入原页面脚本 |

顶栏的“复制代码 / 复制补丁”用于快速带走结果。交付窗口提供源码、diff、CSS 等可用标签，并说明当前结果适合放在哪里。

## 源码与最小 diff

源码模式在原文件的字符串位置上做局部修改，支持 HTML `style` 属性、React `style` 对象，以及 Vue 静态 / 绑定样式。无关代码、注释、换行和格式尽量保留，不重新序列化整个文件。

推荐先查看 diff，确认改动只涉及你调整的目标，再下载修改后的文件。在应用到原项目之前，保存原文件或使用 Git 提交。

若导出的是 unified diff，可以在项目根目录检查后应用：

```sh
git apply --check miweb.patch
git apply miweb.patch
```

`miweb.patch` 是示例文件名，使用你实际下载的 diff 路径。若原文件在导入后又被修改，检查可能失败；重新导入最新源码并再次调整。

Windows 剪贴板可能将换行转换为 CRLF。需要保留原文件换行时，优先下载源码文件或使用生成的 diff。

## CSS 布局补丁

URL 模式根据原页面的选择器生成 CSS，不会还原构建前的 React / Vue 工程。把补丁放到页面已有样式之后，再在原项目运行页面检查效果。

源码模式中的动态节点、属性展开或不能可靠确定有效样式的节点，也可能回退为补丁。交付窗口会说明哪些修改没有直接落入源码。

原页面结构或选择器变化后，补丁可能不再匹配。需要长期维护时，建议将对应调整整理回项目的原样式定义。

## JavaScript 布局补丁

内联 `!important`、级联层中的重要声明或过高的选择器优先级，可能让 CSS 无法可靠覆盖。此时 Miweb 提供 JavaScript 补丁，并在交付窗口明确说明使用位置。

请将补丁放在目标元素已出现后执行的位置，并检查加载时机。如果页面会在运行中重建元素，单次补丁不一定覆盖后续节点。

## 应用后检查

在原项目运行页面，检查目标元素、重复组件实例和不同屏幕宽度。Miweb 中预览的是快照，真实页面的动态行为仍需在原项目里确认。
